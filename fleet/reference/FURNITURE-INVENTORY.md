## 3. Burial and float on the installed fleet

**The check.** Milford's rule (`tracks/milford-road-course-lm/source/furniture/pass3/scripts/seat_built.py`), generalised to every wall / rail / post / lamp class:
- Per 0.5 m plan cell, take the object's top minus the **highest** built ground (1GRASS / 1KERB / 1ROAD / PADAPRON) under the cell.
- Take the object's lowest vertex minus that ground.

It was run on the gate OBJs (`data/track.obj`, written from the kn5) of the newest Mac build workshop each track has. These are not the installed builds: those live on the PC. Where the furniture config is byte-equal to the installed one, the result carries over; otherwise the table says so.

**The gates cannot see this failure.** None of drive_test, audit_mesh, kn5_ground_check or house_seat asks whether a wall *shows*. They ask whether it stands on ground, and a buried wall does.

## 5. Caveats

- **Positions.** Positions read off the NAIP crops in this inventory are pixel reads on downscaled crops, good to about ±2-10 m. `s` values are projections onto each port's `data/centerline.local.json`. A pass re-reads every vertex at full resolution, as Milford's `grid.py` did.
- **Heights.** Heights marked "from shadow" are estimates, not measurements. A pass either solves them against the image's sun, as Milford's `sun.py` did, or marks them [invented].
- **Lidar dates.** A lidar flight can predate the furniture. Milford's 2017 flight predated its rails. Every lidar height needs its flight date beside the photo's date.
- **Tool.** The burial check in section 3 is `expose.py`, a read-only generalisation of `seat_built.py`. It lived in the Mac session scratch and is not committed. Its numbers for Milford-style rails agree with `seat_built`'s rule: the highest built ground per 0.5 m cell.
- **Base.** This file sits on `origin/main` (554fe6b), which has `fleet/reference/`.

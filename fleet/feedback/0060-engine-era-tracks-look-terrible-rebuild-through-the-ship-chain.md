## Evidence

- Lake Murray 0.19.1 was not built by an engine version. It was built by the chain `tools/ship_sd.sh`
  (header, lines 1–60): the engine drafts into `loop.blend`, scripted and hand authoring edit that blend,
  `scripts/ac/build_kn5_loop.py` preps it, the AC add-on exports, the four gates run on the built kn5, then
  install. The generalised form, `tools/ship_track.sh <track>` + `tracks/<track>/ship.json`, landed 2026-10-11
  (ledger 0048 "P1, the ship chain") and had one customer.
- Every other built track in `tracks/` is `scripts/build.sh` output (the V1 pipeline: `gps → elev → project →
  mesh → env → blend → kn5 → pack`), generated end to end. `tracks/sand_creek_raceway/README.txt`: "generated by
  prodrive-ac-builder". `fleet/REALISM.md` §1 convicted this pipeline on 2026-08-06 ("gates measure
  self-consistency; believability is authored"); its `env` stage is where the furniture Kevin saw comes from.
- The road signs on High Plains: `scripts/environment/signs.py` + `build_env` place a street-name sign atlas at
  every junction for every archetype, `race_circuit` included (`scripts/build.sh` line `active env … build_env`).
  The chain never runs `build_env`; signs come only from `signs.json` through `tools/author_signs_blend.py`.
- Why no other track had gone through the chain: `tools/ship_track.sh` `draft_underlay` (line 148 before this
  entry) exited with "no blend yet: scripts/blender/underlay.py (V3-PLAN P2 step 3) is not written". The
  Lariat, the chain's first intended customer, was shelved 2026-10-12 (ledger 0054) before anyone wrote it.
  `tracks/lookout-lariat/ship.json` `_doc`: "Today the chain stops at 'no blend yet'".
- The research handoffs of 2026-10-28 (`docs/RESEARCH-HANDOFFS.md`, both dossiers' §11) prescribed the V1
  pipeline to the build sessions. They built what they were told.

## Diagnosis

Two causes, one standard-level and one mechanical.

1. **Standard.** Nothing in `fleet/` said that the V1 pipeline was retired *as a way to build a track*.
   REALISM §1–§2 demoted it to a draft generator in doctrine, `docs/V3-PLAN.md` planned the chain, but
   `scripts/build.sh` kept building complete tracks, `fleet/DEFINITION-OF-DONE.md` kept granting T0/T1 to its
   output, and the dossier template's §11 said "which pipeline stages in what order". A build session following
   the written record built the old way and was right to.
2. **Mechanical.** The chain could not take a non-San-Diego track: the generalised draft builder did not exist,
   and the gps stage (`scripts.gps.centerline`) built only OSM routes, so a KML or traced track had no draft
   step either.

## Fix (this entry's change, 2026-10-28)

- **`scripts/blender/underlay.py`** (new, `scripts/blender/`): the engine's `data/track.obj` into `loop.blend` as
  `GEN_road` / `GEN_kerb` / `GEN_wall` / `GEN_terrain` / `GEN_misc` + `GEN_refs`, in the prep's own frame, object
  names = OBJ group names (the prep keys on them), `AUTH_*` never touched, the scene never reset, a report in
  `data/underlay.report.json`; `--plan` without Blender. Tests: `tests/blender/test_underlay.py` (the frame, the
  collections, the plan, and with `bpy` the build twice with an `AUTH_*` object surviving).
- **`tools/ship_track.sh`**: two draft steps, `aerial` and `mesh` (both `--draft-only` data steps); the
  "no blend yet" text no longer says the underlay is unwritten. `scripts.gps.centerline` dispatches on
  `source.type` (osm / kml / from_track; aerial is its own step), so `draft_gps` serves every source.
- **Four `ship.json`** (Milford, Exotics, Sand Creek, High Plains): draft `gps|aerial → elev → project → (widths)
  → mesh → underlay`, no authoring yet, prep → split → export → AI → verify → gate OBJ → track folder → map,
  gates `drive_test_street → audit_street → kn5_ground`, install under `install_folder`. Workshops at
  `C:/Users/Owner/Documents/k10-workshops/<track>`. Sand Creek runs its `full` layout; the reverse layout
  waits on a declared start (`_layouts_v3_owed`).
- **Standard**: `fleet/DEFINITION-OF-DONE.md` — the four tracks' engine-era tiers are withdrawn; a tier is
  claimed through the chain or not at all. `docs/RESEARCH-HANDOFFS.md` and both dossiers' §11 rewritten to
  the chain. **Owed to this entry, in `fleet/LAWS.md` and `fleet/STANDARDS.md`:** the sentence that
  `scripts/build.sh` is a draft, never a track (the fleet rebuild and consolidation plan carries it).

What it costs: the first pass of each track ships the *draft* through the chain — no signs, lamps, race
layouts or trees — so the seat can judge the construction before any authoring. That is the doctrine
(REALISM §2 Job 3), not a shortcut.

**The frame, found underneath (the finding of the day).** Why was the mesh mirrored at all? `mirror_x: true` +
`true_north_rotation_deg: 180` in every V1-era config are the V1 OBJ program's own import convention
(`build_kn5.py` imported `(x, −z, y)`, which reads mirrored in-game, so build_mesh mirrored east at the source
and the model was yawed 180° for the sun). The loop prep imports `(x, z, y)` and the exporter writes `(x, z, −y)`:
kn5 `(E, up, −N)`, geographically right with **no mirror and no yaw** — Lake Murray 0.19.1 is `mirror_x: false`,
`true_north 0`, and V1-with-mirror-and-180 is the same frame as loop-with-neither (the algebra: mirror E then yaw
180° = negate N). So the chain on a V1-frame config ships a **mirrored** track — every turn the wrong way — with the
sun 180° off, and every gate is self-consistent and blind to it (`kn5_ground_check` even applies the 180° yaw the
prep never made). Fix: the four configs set to the chain's frame (Exotics' T2 bank from −6.0 to +6.0, the natural
sign, `profile.py`); `tools/ship_track.sh` refuses the V1 frame before any copy; the prep's grid facing corrected to
the measured `atan2(E, −N)` convention (ledger 0047; the `atan2(E, N)` that stood there faces a north-bound grid
south, and `verify_kn5`'s single-layout branch has no facing check). GATES-CHANGELOG 2026-10-29. IMI, Pueblo,
Aspen, Grand Junction, Pikes Peak and Second Creek still carry the V1 frame and are refused until their turn.
